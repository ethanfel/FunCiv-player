**A — A pending Save can overwrite subsequent edits**

Source: [composer-view.js:143](/media/p5/FunCiv-player/renderer/composer/composer-view.js:143).

Save sends the current session through IPC, then replaces `this.session` with the returned snapshot and unconditionally sets `dirty=false`. The editor remains usable during the wait. Changes made after the request are therefore overwritten when it completes; switching sessions while waiting can also be affected by the same unguarded assignment.

Reproduction: delay the save response, edit the session name, then release the response. The code-level probe reverted the name to `Audit song` and cleared the dirty flag. The Electron probe edited the actual name input during a pending save and observed `{name: 'Preview song', dirty: false}` afterwards. This is an in-memory overwrite; the earlier saved snapshot is intact, but the newer edit is neither current nor saved.

Fix: capture session ID and edit generation alongside the saved snapshot. Apply the returned revision to that snapshot's bookkeeping, preserve newer current state, and mark clean only if the editor still contains the saved generation. Add coverage for editing, opening another recipe, and consecutive Save requests during an outstanding save.

**B — The greedy planner mistakes a bad choice for insufficient footage**

Source: [index.mjs:132](/media/p5/FunCiv-player/packages/composer-core/index.mjs:132).

The scarcity ordering helps, but selection still commits to random choices without reconsidering them. Overlapping folder pools can consume the only source needed by later sections.

Reproduction, default seed 1: three one-second sections require `X, Y, Y`. Three one-second videos have categories `a: X`, `b: Y`, `z: X+Y`. The valid unique arrangement is `a, b, z`, but assembly fails with `Cannot fill Section 3 at 2.0 s without repeating a video`. The fixture validates the witness arrangement's duration, coverage and category membership.

Fix: use an assignment algorithm or bounded backtracking across shared video identities. Fixed regions are a matching problem; automatic clip-length sections also need duration-aware choices. Distinguish a proven shortage from a search that exhausted its budget. Test overlapping pools, variants of one video, locked placements and duration limits. Draft proposals use the same planner, so this failure can also hide an otherwise feasible draft offer.

**C — Accepting drafts discards the plan that justified the offer**

Sources: [draft-proposal.mjs:6](/media/p5/FunCiv-player/packages/composer-core/draft-proposal.mjs:6), [composer-view.js:158](/media/p5/FunCiv-player/renderer/composer/composer-view.js:158).

The trial treats every linked HF candidate with a remote L0 descriptor as script-ready. It finds an arrangement and requests only the scripts used by that arrangement. After downloading those scripts, the UI runs a fresh arrangement against the now smaller ready pool. Identical seeds do not produce identical choices when the pool changes.

Reproduction: four one-second sections require `X, X, Y, Y`. Videos `0..5` have categories `XY, XY, X, XY, Y, Y`; only video 0 is approved and initially script-ready. The remaining five are linked drafts awaiting scripts. The offered plan is `0, 2, 5, 3`, with fetch IDs `2, 3, 5`. Mark those downloads ready and rerun the current acceptance path: it fails at Section 4 despite having every asset required by the offered plan.

Fix: retain the exact proposed placements, validate their fetched assets and current session/catalog state, then commit that plan. Show another offer if its prerequisites changed. Keep consent and placement changes in one undo operation.

**D — HF catalog updates break cache and saved-asset continuity**

Sources: [composer-service.cjs:226](/media/p5/FunCiv-player/electron/composer-service.cjs:226), [composer-service.cjs:229](/media/p5/FunCiv-player/electron/composer-service.cjs:229), [composer-service.cjs:298](/media/p5/FunCiv-player/electron/composer-service.cjs:298).

Cached scripts are retained only if the entire repository commit is unchanged. Saved bindings also include that repository commit. An unrelated HF update can therefore discard already verified scripts and invalidate a saved recipe even when that recipe's video, variant and published script descriptors are identical. Exact matching local sidecars can refill the script cache during relinking, but do not prevent the commit binding from changing.

Reproduction: save a recipe with a cached HF script and a valid local video, then refresh a mocked HF catalog whose only change is the repository commit. `script_ready` becomes false and the saved recipe fails with `differs from the saved session`. Next replace the variant ID: refresh removes the original catalog record entirely, and the saved recipe fails with `Resolve the selected clips first`.

This is particularly relevant when a validated upload replaces a draft. Historical asset retention was already documented as a limitation in [IMPLEMENTATION.md:26](/media/p5/FunCiv-player/docs/IMPLEMENTATION.md:26); this audit demonstrates its effect and the additional unchanged-script cache invalidation.

Fix: cache scripts by validated content hash and preserve asset records referenced by saved recipes. Separate current discovery metadata from immutable script/media bindings. Keep a referenced draft resolvable until the user explicitly adopts its replacement; do not silently substitute a different script. This does not require duplicating every local video.

**E — A downloaded replacement inherits a stale local-video link**

Sources: [composer-service.cjs:126](/media/p5/FunCiv-player/electron/composer-service.cjs:126), [composer-service.cjs:271](/media/p5/FunCiv-player/electron/composer-service.cjs:271).

An HF entry linked to a scanned file receives `local_video_id`. If that source disappears and Resolve downloads a replacement into the app cache, the resolver updates the file path and stats but retains the old local ID. Relinking accepts an independent cached path only when `local_video_id` is absent, so the next relink marks the downloaded copy unavailable.

Reproduction: scan and link a local file, remove it, run Resolve with mocked successful metadata/download/probe operations, verify that the new cached file exists, then call relinking. Availability changes from true to false. Actual HTTP and codec decoding were mocked; the resolver, file creation/stat checks and relinker ran.

Fix: clear or replace the previous link when adopting a cached download. Represent the active video source explicitly and validate it independently of stale scan provenance. Test local-to-cache fallback and reconnecting the original drive.

**F — A failed root scan leaves misleading availability**

Source: [composer-service.cjs:108](/media/p5/FunCiv-player/electron/composer-service.cjs:108).

`rescan` catches a missing-root error and adds a warning, but never marks that root's native local records unavailable. HF linking checks its own paths; ordinary local rows retain their earlier state.

Reproduction: index a temporary directory, rename that exact directory, then rescan. The result has a warning, but its local clip remains `available:true` and assembly can select it. Playback or saving fails later when the file is accessed.

Fix: model root availability and recompute effective clip readiness on failed scans. Display the root as offline with a reconnect/relink action. Preserve its metadata for recovery. Test missing roots, permission failures and successful reconnection.

**G — Offline media prevents saving timeline work**

Source: [composer-service.cjs:280](/media/p5/FunCiv-player/electron/composer-service.cjs:280).

Saving an assigned recipe calls `clipsForSession`, which requires its media files and bindings to validate immediately. This couples persistence to playback readiness. A disconnected drive prevents saving edits even though the recipe itself is valid.

Reproduction: save a valid one-clip recipe, rename its library root, edit the recipe name and save again. The save fails with `ENOENT` from the source-video stat call. Existing data is not overwritten, but the current edits cannot be persisted through Save.

Fix: allow saving structurally valid recipes with unresolved media references, retaining their known bindings and recording readiness separately. Require successful resolution for preview, device preparation and export. Add autosave/recovery after persistence can safely preserve incomplete work.

**H — Escape misses a source drag after the focused handle is rebuilt**

Sources: [region-editor.js:16](/media/p5/FunCiv-player/renderer/composer/region-editor.js:16), [region-editor.js:143](/media/p5/FunCiv-player/renderer/composer/region-editor.js:143).

Starting a source-window drag rebuilds the inspector, removing the focused handle. Focus falls to `BODY`. The Escape handler exists only on the Composer root, so the subsequent keyboard event does not reach it.

Reproduction in Electron: focus the source window, press and drag, then press Escape. Observed `{focus: 'BODY', dragStillActive: true, changed: true}`. The DOM-only reproduction independently confirms the event path.

Fix: use the same window-level Escape, pointer cancellation and blur lifecycle already implemented by [section-editor.js:16](/media/p5/FunCiv-player/renderer/composer/section-editor.js:16). Restore the original placement and leave undo unchanged on cancellation. Test with focus removed and pointer capture lost.

**I — Missing translations fail the general test suite**

Sources: [en.json:125](/media/p5/FunCiv-player/renderer/locales/en.json:125), [en.json:1450](/media/p5/FunCiv-player/renderer/locales/en.json:1450), [locale-key-parity.test.js:84](/media/p5/FunCiv-player/tests/unit/locale-key-parity.test.js:84).

`de`, `es`, `ja`, `ko`, `ru` and `zh` lack both `nav.composer` and `session.source.composer`. French has the navigation key but lacks `session.source.composer`. All seven parity cases fail; the runtime implication is translation fallback, not a demonstrated application crash.

Fix: add the missing keys across shipped languages, then migrate Composer's hardcoded UI text into the existing localization system. Run the general unit suite on ordinary PRs: [composer.yml:21](/media/p5/FunCiv-player/.github/workflows/composer.yml:21) only runs Composer tests, while [build.yml:47](/media/p5/FunCiv-player/.github/workflows/build.yml:47) runs the broader tests during the release workflow.
